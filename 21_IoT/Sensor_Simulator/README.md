# 📖 About

Sensor Simulator generates reading logs for a small fleet of **virtual sensors** — a living-room temperature probe, a humidity sensor, and a hallway motion detector — entirely in-process with numpy's seeded RNG (`np.random.default_rng`). Temperature and humidity follow a smooth diurnal cycle plus Gaussian noise; motion is a Bernoulli 0/1 process.

The point of the project is *reproducible telemetry*: the same seed produces byte-identical CSV logs on every run, the log validates strictly when reloaded, and **fault injection** (spike, drift, stuck, dropout) can corrupt a chosen tick window so downstream tooling has realistic failures to chew on. The bundled `data/sensor_sample.csv` is generated by the CLI itself and the demo asserts its simulation matches it **exactly**.

**Everything is simulated locally.** There is no network, no API keys, no MQTT broker, and no real hardware — the "sensors" are functions returning numbers. The demo runs in well under a second and is fully idempotent.

# ✨ Features

- Three sensor models: temperature/humidity (sine cycle + noise, humidity clipped to 0–100) and motion (binary Bernoulli)
- Deterministic seeding per sensor via `default_rng([seed, crc32(name)])` — order-independent, byte-identical logs
- Four fault kinds injected over tick windows: `spike`, `drift`, `stuck`, `dropout`
- CSV logging with strict reload validation (columns, numeric values, timestamps, fault labels, motion binarity, monotonic time)
- Per-sensor summary table: count, min/max/mean, injected-fault counts
- `--demo` verifies against the bundled sample, re-runs deterministically, and round-trips a temp CSV
- 55 passing pytest tests

# ▶️ Run

```bash
# Offline demo: simulate, verify against bundled sample, summarise
python src/main.py --demo

# Simulate 96 ticks and write a CSV log
python src/main.py --log readings.csv --ticks 96

# Inject a fault window (SENSOR:KIND:START:END, repeatable)
python src/main.py --log readings.csv --fault living_room_temp:spike:30:33

# Summarise an existing log
python src/main.py --replay readings.csv

# Summary as JSON
python src/main.py --log readings.csv --json summary.json
```

Input schema (header row required):

```csv
timestamp,sensor,kind,value,fault
2026-03-01T00:00:00Z,living_room_temp,temperature,21.874213,none
2026-03-01T00:00:00Z,hallway_motion,motion,0.0,none
```

(`timestamp` is ISO-8601 UTC ending in `Z` and must be non-decreasing; `kind` ∈ temperature/humidity/motion; `value` is numeric, motion strictly 0/1; `fault` ∈ none/spike/drift/stuck/dropout.)

**Exit codes:** `0` = success · `2` = usage/schema/fault error.

# 🧠 How It Works

```text
SensorSpec fleet (name, kind, base, amplitude, noise, probability)
        │
        ▼  per sensor: default_rng([seed, crc32(name)])
  ┌────────────────────────────────────────────────┐
  │ for tick in 0..N-1  (tick-major, time sorted)  │
  │   value = sine cycle + Gaussian noise          │
  │          (motion: rng.random() < p → 1 else 0) │
  │   fault window? spike +15 / drift +1.5·elapsed │
  │                    stuck → freeze / dropout →  │
  │                    row omitted                 │
  │   humidity clipped to [0, 100], round to 6 dp  │
  └────────────────────────────────────────────────┘
        │
        ▼
  CSV log ──► load_log (columns → strings → numeric →
             timestamps → monotonic → motion 0/1) ──► summary
```

Details worth knowing:

- **Tick-major row order** keeps the whole log timestamp-monotonic even though each sensor has its own RNG stream.
- **6-decimal rounding** is deliberate: it survives pandas' CSV float formatting exactly, so `log → load → equals` round-trips byte-for-byte (the demo proves it in a temp directory).
- **Dropout removes the row** (a lost reading), while spike/drift/stuck keep the row and label it in the `fault` column — so a replay can distinguish *missing* data from *corrupted* data.
- Fault windows are validated before simulation: unknown sensor, out-of-range ticks, and overlapping windows all fail fast.

# 📚 Concepts Covered

- Deterministic simulation with per-entity RNG streams
- Seeding pitfalls: why `hash()` is salted and crc32 is stable
- Fault injection modelling: spikes, linear drift, stuck values, data loss
- Long-format telemetry logs (timestamp, sensor, kind, value, fault)
- CSV round-trip exactness and float formatting limits
- NaN handling: empty cells → `fillna` before `astype(str)`, `to_numeric` coercion before assignment
- Fail-fast CLI design: validate flag inputs before expensive work
- Idempotent demos with bundled golden data and self-assertions
